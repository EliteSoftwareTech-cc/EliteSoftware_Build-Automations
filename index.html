Welcome to the EliteSoftware SDK

This document serves as the official guide to the EliteSoftware native C++ build environment. Utilizing these tools allows you to maintain aesthetic compliance, enforce consistent versioning, generate rich documentation, and perfectly build Win32 applications.

Environment Setup & Global Paths

The EliteSoftware Dev Environment uses custom nested path variables to ensure all tools are universally accessible without cluttering standard project directories.

EliteBuildLocator

Description: Scans all drives to locate standard build tools (MSBuild, g++, windres, ISCC, etc.) and native Elite tools, injecting them into a custom system-wide path variable with newer tools prioritized.

Path Variables Created: %ELITE_BUILD_X64% and %ELITE_BUILD_X86%.

First Run: Automatically prompts the EliteSoftware EULA. Acceptance sets a registry marker under HKCU\Software\EliteSoftware\EULA.

CLI Tools & Utilities

EliteBuild (The Entry Point)

Description: The only executable required in a project root. Reads EliteBuild.config and orchestrates compilation via the global toolchain.

Usage: EliteBuild.exe

EliteVersionBumper

Description: Natively parses C++, Headers, RC, and Config files to bump standard 4-decimal version numbers (Major.Minor.FeatureAdd.BugFix).

Usage: EliteBuild_VersionBumper.exe "C:\Path\To\File" major|minor|feature|bugfix

EliteReadmeGenerator

Description: Flushes heavily formatted markdown templates directly into projects depending on the architecture type (1-5).

Usage: EliteReadmeGenerator.exe 1 "MyProject"

Usage & Examples

If any tool is launched via double-click (no arguments provided), it falls back to an interactive console session to safely request parameters.

C:\> EliteBuild_VersionBumper.exe
[INFO] Interactive Mode Triggered.
Please enter the file path to bump: changelog.md
Please enter the part to bump (major/minor/feature/bugfix): bugfix
[INFO] Successfully bumped version.

Absolute Logging Standards

Every single EliteSoftware CLI tool natively logs every action to its local directory (alongside the `.exe`). A timestamped `.log` file is instantiated upon every run, ensuring a perfect forensic trail of pipeline compilations.
